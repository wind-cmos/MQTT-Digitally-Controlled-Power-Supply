## 1. 总结

主要信号引脚分配仍可成立，但当前电路不宜直接定版投板。最优先解决：BOOT0 控制逻辑、CAN 隔离地被合并、USB 自供电路径的防误使能与 VBUS 检测、未确认的屏幕供电。

已按 ST 官方封装/复用数据检查 U1 的 176 个物理脚，追踪 RN 串阻，并检查 DSI、SDRAM、SPI Flash、ESP UART/控制、CAN3 和 MII 对端：未发现新的物理脚号/复用冲突。当前为 122 个已分配 GPIO、9 个备用 GPIO、45 个电源/专用脚。该检查不是固件初始化验证。

## 2. 外部按钮可以控制，但当前 U7 不能实现切换

当前 U7=74AUP1G74DC：CP.1=USER_SW，D.2=3.3V，Q#.3=BOOT0，RD#.6、SD#.7 均为高。SW1 按下把 USER_SW 接地。

| 状态 | 当前逻辑结果 |
|---|---|
| 上电尚未收到有效时钟沿 | 没有有效异步初始化，Q# 状态不能保证 |
| 按下按钮 | CP 下降沿，不锁存新的 D |
| 松开按钮，假设另加了上拉 | CP 上升沿锁存 D=1，Q#=0，即 BOOT0=0 |
| 再按、再松 | 仍为 BOOT0=0，不会来回翻转 |

当前 USER_SW 还没有外部上拉，C35=10nF 本身不能形成可靠高电平；上述“松开上升沿”已经是假设补上拉后的最好情况。PI8 软件上拉不能保证 MCU 启动前的状态。BOOT0 上的 R5=10k 下拉不能压过 U7 推挽输出的高电平。

依据：[Nexperia 74AUP1G74 功能表与推荐工作条件](https://assets.nexperia.com/documents/data-sheet/74AUP1G74.pdf)。

### 对本项目更合适的按钮用法

你采用“内部 Bootloader + 外部新旧镜像”，日常升级通常不需要拉高 BOOT0：

1. 断开 U7.3 对 BOOT0 的驱动，R5=10k 下拉保留。
2. SW1 保留接 USER_SW/PI8，增加约 10k 上拉到 3.3V；C35 可用于 GPIO 输入滤波，固件再消抖。
3. 内部 Flash 的 Bootloader 启动后读取按键或升级标志，决定升级、恢复旧镜像还是运行应用。
4. 另留独立 ROM 救援 BOOT 按钮：3.3V 经约 1k 和按钮接 BOOT0；正常由 R5 下拉。先按住 BOOT，再复位 MCU。必须先断开 U7 输出，不能直接用按钮与推挽输出对顶。
5. 硬件 BOOT0 的作用由 BOOT_ADD0/BOOT_ADD1 选项字节决定，默认用户 Flash/系统 ROM，调试时核对选项字节。[ST 官方 F769 评估板手册 §6.5](https://www.st.com/resource/en/user_manual/um2035-evaluation-board-with-stm32f769ni-mcu-stmicroelectronics.pdf)

这是保留外部按钮控制的方案，并非要求只能用电脑发升级命令。

### 若坚持保留 U7 做“按一次翻转一次”

| U7 引脚 | 修改要求 |
|---|---|
| D.2 | 断开与 3.3V 的连接，改接 Q#.3，形成翻转反馈 |
| Q#.3 | 保持连接 BOOT0 |
| CP.1 | 有效上拉，并加入可靠的硬件消抖/边沿整形 |
| RD#.6 | 保持高 |
| SD#.7 | 从固定高改为独立上电初始化信号，施加有效低脉冲，使 Q=1、Q#=0 |
| VCC.8/GND.4 | 3.3V/GND，并保证近端 100nF 去耦 |

不要把 SD# 简单绑到每次都会动作的 MCU NRST，否则选好 BOOT0=1 后，一按复位又被清回0。SD#/RD# 不得同时有效。按键翻转完成后，仍须复位 MCU 才改变启动入口。这个方案比“Bootloader 读 USER_SW”复杂，不能只把 D 脚改接反馈就认为已经完成。

## 3. TPS2051BDBVR 保留方案

现有接线：U11.IN.5=电脑 +VBUS，OUT.1=板载 +5V，EN.4=PD5/USB_OTG_FS_PSO，OC#.3=PD4/USB_OTG_FS_OC；R42=10k 对 EN 下拉。

TI 手册 §8.3.1 明确说明禁用时阻断 IN→OUT 和 OUT→IN。因此不能说保留它就必然反灌。问题在于使能后会建立电脑 VBUS 与板载稳压器之间的供电通路；它不是双电源自动择源器。[TPS2051B 手册](https://www.ti.com/lit/ds/symlink/tps2051b.pdf)

| 项目 | 本次建议 |
|---|---|
| U11、PD4、PD5 | 全部保留，不释放引脚 |
| R42=10k | 保留下拉，保证复位时默认关闭 |
| PD5 固件 | 自供电 USB Device 模式，始终输出低，不调用主机模式的 VBUS 供电使能代码 |
| 防误使能硬件 | 推荐 OUT 改名 USB_SW_OUT，再经一个默认不装的 0Ω/跳线接板载 +5V；两端必须不同网名。保留 U11 但物理隔断并接路径，后续确有用途再验证装配 |
| OC# | 目前未发现外部上拉，建议加 10k 至 MCU 3.3V，PD4 作输入；不需要把它拉到5V |
| C54 | 已由47uF改成2.2uF，不再列为旧47uF问题；仍须核算端口有效电容/插入浪涌 |
| C54/C55 地端 | 二进制地符号未明确 TEXT，辅助解析不能定性为悬空；在 Altium 显式命名 GND 并高亮核对 |
| CC1/CC2 | 各5.1k下拉保留，当前为设备端角色 |
| D+/D- 串阻 R23/R24 | 当前22Ω；F769 USB FS PHY 内置终端，建议保留焊盘、按 ST 指南以0Ω起调，再用信号质量验证，而不是断言22Ω必不工作 |

若采用默认断开的 OUT 跳线，USB 数据通信不依赖该跳线闭合，板子仍由12V供电。若未来希望 USB 也给主板供电，要另做择源/防反灌设计，不能仅把跳线焊上。

### VBUS 检测仍须修改或完整计算

R44/R43 仍为5.1k/5.1k，接 PA9。用于原生 USB VBUS sensing 时，按 ST 指出的典型200uA负载估算，5V输入下节点约为：

`5V / 2 - 200uA × (5.1k || 5.1k) = 1.99V`。

这不是稳定识别 VBUS 的可靠设计依据。普通 GPIO 检测与原生 VBUS sensing 的输入条件不同，不能混用阈值或只按无负载2.5V判断。[ST AN4879，VBUS 检测与 FAQ](https://www.st.com/resource/en/application_note/an4879-introduction-to-usb-hardware-and-pcb-guidelines-using-stm32-mcus-stmicroelectronics.pdf)

可选改法：移除这组分压，使用2N7002反相检测；源极接GND，栅极经10k接VBUS并加1M对地下拉，漏极接PA9并经10k上拉到MCU 3.3V。有VBUS时PA9低，无VBUS时高。PA9改普通GPIO、关闭USB原生VBUS sensing，由固件控制连接/断开，不能仅换硬件不改程序。检测用轮询可避免与PB9共用EXTI9。

## 4. CAN：本次新发现的隔离与供电问题

U19.4 GND1 与 U19.7 GND2 现在都接名为 GND 的网络，隔离两侧被原理图连接绕过。即使器件型号是隔离型，这种接法也不再提供系统级电气隔离。

另外，U19.8 和 U21.1 的电源叫 **+5**，主板降压输出叫 **+5V**。在当前六页中，+5 只连接 U19.8、U21.1、C100.2，没有发现板内电源来源。因此：

- 若准备从 U21 引入外部5V，需要明确外部供电，并保持它和主控侧电气隔离。
- 若以为 +5 已连上板载 +5V，则实际上没有连上；不能凭符号都像5V就认为同网。
- 仅把 +5 改成 +5V 也不能实现隔离，只会变成板内共电源、共地。

建议修改表：

| 位置 | 目标连接 |
|---|---|
| U19.1 VCC1 | 主控 +3V3 |
| U19.4 GND1 | 主控 GND |
| U19.2/.3 | CAN_TX/PA15、CAN_RX/PA8，原分配保留 |
| U19.8、U21.1、C100.2 | 改为 +5V_CAN_ISO |
| U19.7、U21.2、C100.1 | 改为 GND_CAN_ISO，删除这些位置的主控 GND 连接 |
| U21.3/.4 | CANH/CANL，保留 |
| 电源来源 | 外部总线侧独立5V，或本板增加合适隔离DC/DC；两者选定一种并标明方向 |
| C100 | 保留100nF，跨总线侧 VCC2/GND2；逻辑侧1/4脚也保证近端100nF |
| R58=120Ω | 总线末端才装，建议串跳线或DNP装配选项 |

CA-IS1044S 的 VCC2 推荐4.5-5.5V，VCC1 支持3.3V；它不内置跨隔离供电模块。外部电源要相对于主控域真正隔离，不能把普通共地5V叫“隔离5V”。TVS和必要的共模器件、PCB隔离间距仍需按系统环境落实。[川土 CA-IS1044S 手册](https://e.chipanalog.com/Public/Uploads/uploadfile/files/20240611/CAIS1044SdatasheetVersion1.05en.pdf)

### 其他设计/固件约束

- 新增R48/R65=10k与MCU侧R2/R3=4.7k并联，同一I2C线上等效约3.2k；不是必错，也不是两条独立I2C。一般一组足够，按总线电容/上升时间/灌电流确定装配。若屏幕独立掉电，另检查I2C和复位线倒灌。
- U20外部Flash的WP/HOLD上拉而未接ESP SPIWP/SPIHD，当前应按DIO/DOUT使用，不要配置QIO。U16/U17各4MiB，片选上拉已补；外部Flash只是固件存储，升级掉电恢复、校验、版本和回滚属于Bootloader软件。
- CAN是CAN3的经典CAN控制器，隔离收发器本身不会让STM32F769获得CAN FD能力。
- PHY当前为MII，PC9/MCO2需25MHz，PC0低有效复位；不要只在软件改成RMII。MDIO的R45=2.2k可按手册建议1.5k调整，时序需实测。
- U3把5V线性降到3.3V，损耗约1.7V乘实际电流；1A就是1.7W。需核算F769、SDRAM、PHY、ESP和屏幕的总负载/瞬态及散热，不能只凭稳压器标称3A判断。
- MP1584反馈210k/40.2k对应约4.98V；EN分压20k/10k在12V时约4V。该分压不是浪涌钳位，电源输入保护、补偿稳定性与热设计仍待验证。
- U6=74HC125接口是3.3V逻辑缓冲，不是RS485或24V工业DI/DO。CN2与背板共享UART_RX/DIN1时不得同时接两个主动发送源。
- SD卡按现连接配置1-bit SDMMC；SWD调试可用，不启完整JTAG以免占用PB4/PA15；SDRAM连接检查通过不代表缓存、MPU、刷新率和时序已验证。
- 蜂鸣器R25=NC时不供电；核对蜂鸣器额定电压后确定供电/装配，Q1栅极增加约100k下拉。PA4的DAC_OUT1在此是MOS开关控制用途。
- 功率板的PWR_DIRECT、PWR_SSTART、OE_SYNC、FAULT须确认上电和失联时的硬件安全状态；不能只靠WiFi/CAN命令或MCU后期初始化保证关断。
- C41/C42的地符号同样存在辅助解析歧义，在AD显式命名GND并高亮验证；本次不把它直接判成已证实的悬空。
- FPC接触面/针1方向、J1屏蔽与机壳地、CAN隔离爬电距离、USB/DSI/SDRAM/RF布线仍需PCB审核。RF网络只有匹配元件，需确保最终确有天线/射频连接器，并修正L4值“1nL”的标注及最终匹配参数。

## 7. 推荐收尾顺序

1. 先确定按钮用于自定义Bootloader还是ROM救援；修正U7逻辑或解除它对BOOT0的驱动。
2. 恢复CAN两域隔离，明确+5V_CAN_ISO来源及接口方向。
3. 保留U11，落实默认关断和硬件隔断装配策略；修正VBUS检测并补OC上拉。
