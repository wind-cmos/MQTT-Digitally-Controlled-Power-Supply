## 3. 优先修改项

### 3.1 BOOT0 仍被 U7 的不确定输出驱动

证据：U7=74AUP1G74，3 脚 Q# 接 BOOT0；2 脚 D、6 脚 RD#、7 脚 SD# 都接 3.3V。STM32 U1.166 接同名 BOOT0，R5=10k 下拉。

问题：没有有效的异步初始化，不能保证上电 Q# 为低；R5 下拉不能覆盖一个主动输出高电平的逻辑门。D 固定为 1，也不能实现每次按键切换 BOOT0 的功能。依据其功能表，这是启动可靠性风险，不是简单换下拉阻值就能解决。[Nexperia 74AUP1G74](https://assets.nexperia.com/documents/data-sheet/74AUP1G74.pdf)

建议：

1. 解除 U7.3 与 BOOT0 的连接；若无其他用途，U7 可不装或移除。
2. R5=10k 下拉保留；需要进入 STM32 ROM 下载器时，用独立跳帽/按钮把 BOOT0 拉高，再复位。
3. SW1 仍接 USER_SW/PI8，增加约 10k 上拉至 3.3V，C35=10nF 可保留。该线上当前没有独立外部上拉。
4. 自定义内部 Flash Bootloader 不要求平时把 BOOT0 拉高；正常从 Flash 启动即可。

### 3.2 USB 电源路径与“仅通信”用途不符

证据：U11 TPS2051B 的 IN.5 接 +VBUS，OUT.1 接板载 +5V；板载 +5V 由 U15 MP1584 产生，还引到 U5.18/.23。PD5 控制 U11 EN，R42 下拉。

不是说现在关断状态已经短路，而是该路径一旦使能就可能把电脑 VBUS 与板载 5V 并接，且不符合已经确认的用途。不能仅靠应用固件永远不拉高 EN 来定义最终硬件。

具体建议：

| 元件/网络 | 处理 |
|---|---|
| U11 | 删除或 DNP，切断 +VBUS 到板载 +5V 的供电桥。不得用 0Ω 替代 IN-OUT。 |
| R42 | U11 删除后可删除。 |
| USB_OTG_FS_PSO / PD5 | 删除 MCU 端网标与控制分支，PD5 释放为备用。 |
| USB_OTG_FS_OC / PD4 | 删除 MCU 端网标与检测分支，PD4 释放为备用。 |
| C54=47uF | USB 端不再需要这颗大储能电容，建议移除/DNP，降低插入浪涌。 |
| C55/C61=100nF | 可用于 VBUS 小容量旁路；明确接到 GND，按接口附近布局决定保留数量。 |
| R21/R22=5.1k | CC1、CC2 各自下拉保留，当前是 USB-C 设备端角色。 |
| D+/D- 与 D4 ESD | 保留，检查 ESD 回流和接口位置；SBU 悬空可保留。 |
| +VBUS | 仅保留检测、接口保护及必要小电容，不与 +5V/+3V3 合并。 |

按此修改后备用 GPIO 从当前 9 个变成 11 个；在 CAD 真正修改前仍按 9 个计算。自供电 USB 设备必须依据 VBUS 的存在连接/断开 USB 功能，不能一直对电脑呈现连接。[ST AN4879](https://www.st.com/resource/en/application_note/an4879-introduction-to-usb-hardware-and-pcb-guidelines-using-stm32-mcus-stmicroelectronics.pdf)

### 3.3 VBUS 检测不宜继续照搬 5.1k/5.1k

R44 从 VBUS 接 PA9，R43 从 PA9 接地，两者均 5.1k。无负载时 5V 得到 2.5V；F769 原生 VBUS 检测启用时存在典型约 200uA 负载，简单估算节点会降到约 `2.5V - 200uA × 2.55k = 1.99V`。因此不能把无负载的 2.5V 当成可靠检测结果。

另外，MCU 的 FT 引脚在整板断电时有独立输入上限，不能笼统认为“5V 容忍”就允许断电直接灌 5V。F769 数据手册的输入极限与对应供电有关。[STM32F769 数据手册，表14和USB特性](https://www.st.com/resource/en/datasheet/stm32f769ii.pdf)

本项目推荐使用 AN4879 的 NMOS 检测思路，避免把 USB 电压直接加到未上电 MCU：

- 新增一颗 2N7002：S 接 GND，D 接 PA9，D 经约 10k 上拉至主板 3.3V；G 经约 10k 接 USB VBUS，G 到 GND 加约 1M 下拉。
- 删除原 R43/R44 分压，PA9 网名可改为 USB_VBUS_PRESENT_N，防止误当成原生检测功能使用。
- VBUS 在时 PA9 为低；VBUS 不在时为高。PA9 用普通 GPIO 输入，关闭 USB 外设的原生 VBUS sensing，由软件依据该输入控制连接/断开。
- PA9 建议轮询，不启用 EXTI9，因为 PB9/SPI4_IRQ 也使用 EXTI9。
- NMOS 的确切封装和脚号按采购型号核对，不能用三极管符号直接替代。

R23/R24 当前是 22Ω。ST 的该类集成 USB FS PHY 已带输出阻抗，建议保留串联焊盘但初始装 0Ω；若保留 22Ω，应以实测信号质量为依据，而不是当作必需值。[ST AN4879，2.6、3.1和FAQ](https://www.st.com/resource/en/application_note/an4879-introduction-to-usb-hardware-and-pcb-guidelines-using-stm32-mcus-stmicroelectronics.pdf)

### 3.4 LCD 电压仍未解决，不能凭接通就确认可用

证据：FPC1.3、FPC1.38 直接接 +3V3；FPC2.4 也接 +3V3。当前没有独立屏幕稳压器。

D350T1013V1 SPEC 第6页电气表的 LCD VDD 为 2.7-2.9V，第7页针脚表却写 2.8-3.3V，资料本身冲突。第6页绝对最大值不是正常供电许可。此前你要求保留独立屏电源设计，目前原理图尚未落实。

建议 FPC1.3 从主板 3.3V 分离，新增独立命名的 LCD 电源，暂按 2.8V 设计并待商家书面确认；FPC1.38 模式高电平随厂家确认的屏 IO 电压，而不是盲目仍接 3.3V。确认范围还要包含 RESET 输入耐压。

PH4 现在未连接本身没有问题。不需要软件断电时，独立 LDO 可以常开，EN 按所选器件要求接固定有效电平；需要软件开关时再恢复 PANEL_PWR_EN。独立电压与是否可软件开关是两件事。

触摸不能直接照抄 LCD 的 2.8V：FT5X16 裸芯片资料给出 2.8-3.6V 电源范围，但模组内部 IOVCC 接法仍需确认，2.8V 标称稳压还须考虑负公差。I2C1 目前由主板 R2/R3 拉到 3.3V，且共享 EEPROM/外部接口。若触摸 IO 电压不同或独立掉电，需处理 I2C/INT/RESET 的电平与反灌，不要把整条共享 I2C 的上拉改接到会关断的屏电源。普通电平转换器不得插入 DSI 差分对。

资料：[模组规格书](<D:/下载/D350T1013V1  SPEC/D350T1013V1 SPEC/D350T1013V1 SPEC.pdf>)；[触摸芯片规格书](<D:/下载/D350T1013V1  SPEC/触摸资料_Touch Data Sheet/D-FT5X16-1212-V0.3(FT5X16 Data Sheet)_Preliminary.pdf>)。

### 3.5 VBAT 与外部辅助电源没有隔离

CR1220 电池正端、U1.6 VBAT、+VAUX、+VAUX_OUT 同网，并通过 CN1.10/U5.3 引出。

如果外部 VAUX 是电源输出，会有向一次性电池充电或电源互顶的风险；如果外部全部是负载，则不能直接认定在充电，但需计算电池带外部负载的寿命。不能只凭 VAUX_OUT 的命名判断方向。

优先方案是将电池/VBAT 作为独立后备域，与外部辅助供电分离；确需双源时增加适合微功耗备份域的防反充/择源设计。未核清方向前，不同时装电池并接入外部 VAUX 电源。

### 3.6 PDR_ON 不能依赖漏装的跳帽

U1.171 仅接 H2.1，H2.2 接 3.3V。装跳帽时可工作；未装时不能保证有效电平。使用内部电源复位监控的方案建议固定接 VDD，或用默认装配的 0Ω 实现，H2 只作明确标识的调试选项。BYPASS_REG 的 R6 下拉可保留。[STM32F769 数据手册，内部复位和稳压器章节](https://www.st.com/resource/en/datasheet/stm32f769ii.pdf)

### 4.1 ESP32-C3 与 STM32 烧录

|---|---|---|
| PG14/157 | USART6_TX，AF8 | U0RXD -> U18.27 |
| PG9/152 | USART6_RX，AF8 | U0TXD <- R49=499Ω <- U18.28 |

这四根线已连接，STM32 可承担 ESP32 ROM 串口下载器；还需相应 STM32 固件，不是业务 UART 自动具备烧录功能。[乐鑫 esp-serial-flasher](https://github.com/espressif/esp-serial-flasher)

| 位置 | 当前事实 | 建议 |
|---|---|---|
| U18.6/GPIO2 | 未连接 | 按官方建议补约10k上拉。它不是实际决定两种启动模式的位，不应宣称“不上拉必然无法启动”。 |
| R48 | XTAL_P 支路串0Ω | 按当前 C3 官方指南改为串联电感，24nH 为初始建议，最终按晶体/PCB验证。C79/C80=15pF 也要匹配晶体负载，不凭频率相同就定值。 |
| L3 后电源 | U18.2/.3 的局部电容 C89 仅1uF；前级10uF在电感另一侧 | 在芯片侧补足约10uF及高频去耦；确认 L3 电流能力和压降，ESP 电源设计至少考虑500mA瞬态能力。 |
| U13.2 | 与 STM32 PG14、ESP RX 直连 | 外部 USB-UART 的 TX 可能和 STM32 TX 争用。增加可断开的跳帽/0Ω，或明确全程保证 PG14 高阻。断开器件两侧网名必须不同。 |

| U20 Flash | SPIHD/SPIWP 未连接到 IO3/IO2 | 当前适合 DIO，不按 QIO 配置。若要 QIO 再补两线；这不是 STM32 的 A/B 槽。 |

ESP_EN 与 ESP_BOOT_N 有按钮下拉，STM32 不应推挽输出高电平与按钮硬顶。建议开漏，默认释放。GPIO8 上拉和 GPIO9 大电容问题已修正，不再列为待改。[ESP32-C3 官方硬件指南](https://docs.espressif.com/projects/esp-hardware-design-guidelines/zh_CN/latest/esp32c3/schematic-checklist.html)

U13.3 的 3.3V 标为参考/板载电源，默认烧录时整板独立供电，不接下载器5V，也不随意把下载器3.3V与板载电源并联。现有四针口配 SW2/SW3 可手动下载，无须为了手动下载强制增加新 USB 口。

### 4.2 STM32 外部双镜像 Flash

| 信号 | STM32 | 对端 |
|---|---|---|
| SPI1_SCK | PG11/154，AF5，SPICLK_2 | U16.6/U17.6 |
| SPI1_MISO | PB4/162，AF5，经RN3，SPIQ_2 | U16.2/U17.2 |
| SPI1_MOSI | PD7/151，AF5，SPID_2 | U16.5/U17.5 |
| A 槽片选 | PG10/153，SPICS_2 | U16.1 |
| B 槽片选 | PG12/155，SPICS_3 | U17.1 |

连接对应，但两颗 /CS 均缺少外部上拉。分别补约10k到3.3V，保证 MCU 复位/升级异常时保持不选中。WP#/HOLD# 的100k上拉可保留。U20 的 /CS 也建议预留外部上拉；ESP 引脚默认上拉不替代整个上电过程核查。

W25Q32 是32Mbit，即每颗4MiB，不是32MB；两颗用于新旧镜像的容量能够覆盖 F769 的内部应用映像。当前是普通 SPI1，不是 QSPI/XIP 接法。[Winbond W25Q32JV](https://www.winbond.com/resource-files/W25Q32JV%20RevJ%2012242024%20Plus.pdf)

安全升级还依赖内部 Bootloader 保护、镜像长度/哈希或签名校验、断电可恢复的状态记录、试运行确认及回滚流程。仅有两颗 Flash 不代表已实现可靠 A/B。AT24C256 是参数 EEPROM，不是 MCU 自主执行 Bootloader 的存储区。

### 4.3 CAN 隔离接口

PA8/123=CAN3_RX(AF11)，PA15/138=CAN3_TX(AF11)，对应 U19 RXD.3/TXD.2 正确。

U21 定义：1=VCC2，2=GND2，3=CANH，4=CANL。总线侧需要 **4.5-5.5V，通常5V**；目前由接口外供，没有看到本板隔离 DC/DC。外部供电可以，但必须真正满足与主板侧的隔离要求。只接 CANH/CANL 不会让隔离侧自动获得供电。[CA-IS1044S](https://e.chipanalog.com/Public/Uploads/uploadfile/files/20240611/CAIS1044SdatasheetVersion1.05en.pdf)

- 建议命名 ISO_5V、ISO_GND，并在接口丝印明确，防止误接12V。
- C?=100nF 已接 VCC2/GND2，保留；逻辑侧 VCC1/GND1 也需要引脚附近的100nF，布局时明确对应器件。
- R58=120Ω 改成可选择装配，只在总线两端启用。
- 预留合适 CAN 总线 TVS/接口浪涌保护；保护回到隔离侧地，不跨接主板地。
- MCU 是经典 CAN 控制器，不能因收发器支持更高数据率就把系统配置成 CAN FD。
- 电源隔离、PCB 爬电距离、连接器和其他跨域信号都影响最终隔离，不能只凭芯片额定耐压宣称整板达标。

### 4.4 以太网 PHY

MII 信号及 RN4-RN7 对应通过检查。PC9/MCO2 经 RN4 接 U14.X1，需输出25MHz；X2 悬空正确。当前不是 RMII 接法，不要只改软件模式。

| 位置 | 问题/性质 | 修改建议 |
|---|---|---|
| ETH_RESET_N | 网络已修复；时序仍需实现 | PC0 普通GPIO，低有效。MCO2/电源稳定后执行复位，按上电和硬复位时序等待；可预留10k上拉。不是 ETH AF。 |
| C66/PFBOUT | 当前4.7uF，低于厂家推荐10uF | C66 改10uF并核对类型/有效容量，PFBOUT 保留100nF，PFBIN1/2各就近100nF；这些脚不能外供3.3V。 |
| R31/R32 | RESERVED20/21 的2.2k上拉接在 R35 磁珠前主3.3V | 改到 R35 后、与 U14.22 AVDD33 相同的模拟电源节点，符合厂家要求。 |
| R45 | MDIO 上拉2.2k | 建议按手册1.5k配置；它不是引脚接反问题。 |
| C99/C100及49.9Ω | 端接中点只接100nF到地，与TI图7-2中点直接接VDD不同 | 建议按参考设计把两个中点接PHY侧3.3V并保留100nF；无充分验证时不要自行改变厂家模拟前端拓扑。 |
| J1/机壳地 | J1.8名为CHS GND但接主GND，CN1.1 PE单独悬空 | 需要明确屏蔽、机壳PE和数字地策略；不能凭名字把网口屏蔽直接认成安全保护接地。 |

必须纠正此前过强说法：C100 的确有滤波/交流端接作用，而且 J1.4/.5 已接3.3V，磁性器件中心抽头可参与直流偏置。因此不能断言当前所有线对“完全无直流偏置、一定不能通信”。确定的是它与 TI 推荐中点接法不同；上表给出保守回归参考设计的建议，而不是未经实测的必坏判定。[TI DP83848C，图7-2及特殊引脚定义](https://www.ti.com/lit/ds/symlink/dp83848c.pdf)

U14.8-12 对 DP83848C 应不连接，当前可保留；不要套用支持 JTAG 的其他后缀型号。上电 strap 采样期间不要用 MCU 推挽驱动 RXD/COL 等配置复用脚。

### 4.6 屏幕背光

模组第9页给出的背光范围为18.9-23.8V，典型电流20mA。当前 U12 TPS61169 与 R20=10Ω 得到典型 `0.204V/10Ω=20.4mA`，在电流和升压能力方面匹配这块屏，不需要把 LEDA 接到3.3V。

- 目前 FB.3、R20.2、FPC1.2 LEDK 同网，D3阴极/输出电容/FPC1.1 LEDA 同网，连接方向正确。
- U12.VIN.5 位于 R19=10Ω 后，该节点没有电容；在 R19 后就近补至少1uF有效输入旁路，可并100nF。R19前的 C56/C57 不能完全替代它。
- C58/C59 按实际高压输出及开路过压选择耐压/有效容量，建议50V级；D3=1N5819WS标称40V，开路保护可能接近39V，加上尖峰裕量偏紧，建议换合适60V肖特基并核对电流/封装。
- CTRL 内置约300k下拉，所以外加47k-100k下拉是抗干扰加强选项，不是“当前无默认关断”。PD12 初始化占空比0，建议在有效图像出现后开背光。
- PWM调光参考范围5-100kHz，20kHz可作为调试起点；不要使用很低频率造成纹波/可闻噪声。[TPS61169](https://www.ti.com/lit/ds/symlink/tps61169.pdf)

### 4.7 SDRAM、EEPROM、SD卡和调试

- SDRAM：16位、4内部bank、12行地址位/8列地址位，64Mbit即8MiB。现有A0-A11正确，无需把NC脚强接A12。检查实际焊接54脚TSOP封装与采购型号，PCB再核查时序/走线，软件验证全地址读写后再启显示DMA。
- EEPROM：U10 A0/A1/A2接地、WP接地，I2C地址0x50，可读写。触摸共享I2C需要确认地址及总线容量，不能因同为I2C就认为地址必然不冲突。
- SD卡：当前只有CK/CMD/D0，是1-bit SDMMC，不是4-bit；不要在固件切4-bit。保留CMD/D0的47k上拉，建议SD_DETECT增加约10k上拉。卡座附近增加适合写入电流脉冲的容量和ESD保护，确认插卡检测开关脚号。
- 调试：H1的SWDIO/SWCLK/SWO/NRST和参考3.3V/地对应。使用SWD，不启用完整JTAG占用已经分配的PB4/PA15。
- 若显示使用DMA2D/LTDC/DSI和外部SDRAM，缓存一致性、MPU属性、总线带宽属于固件验证项；原理图正确不等于图像不会花屏。

### 4.8 外部IO、按键、蜂鸣器及保护

- U6=74HC125、CN2 是3.3V逻辑缓冲接口，不是RS485，也不是可直接接工业24V的DI/DO。4.7k串阻和ESD器件不能充当持续过压/负电压接口方案。
- CN2.1经U6/R9输出到UART_RX/DIN1，同时U5.2也在该网络。若背板和CN2可能各接一个主动UART发送端，必须选择一路或隔离，不能默认两个源同时驱动合法。
- ENC_SW、USER_SW、SD_DETECT 在有效输入状态需要明确上拉；编码器A/B已有4.7k上拉与RC，初始调试保留，结合速度和抖动验证。
- 蜂鸣器R25=NC意味着默认不供电。先确认TMB12A05实际额定电压/有源类型，再确定供电与R25装配；Q1栅极加下拉。PA4网名虽叫DAC_OUT1，当前负载是MOS栅极开关，应按GPIO用途理解。
- PWR_DIRECT、PWR_SSTART、OE_SYNC和FAULT属于数控电源控制/保护接口，需要对端硬件的上电默认关闭和异常关闭机制。不能只靠STM32启动后初始化或WiFi/CAN命令保证功率安全；本轮不凭名称臆定有效极性。

## 5. 工程完整性与原生编译检查

1. 新增GPIO8上拉还是 **R?**，CAN去耦还是 **C?**。执行位号注释，再检查BOM/封装映射。本轮未发现其他跨页重复位号或U1重复物理脚。
2. C41/C42地端、C54/C55地端对应的Power Port在二进制记录里没有明确TEXT。辅助解析不能可靠判断Altium是否使用默认GND；这两处列为**原生编译确认项，不认定已证实悬空**。在AD中把网络名显式设置为GND并高亮确认即可消除歧义。
3. 项目使用多张原理图。编译后检查同名网作用域，特别是ETH_RESET_N、SPIQ_2、ESP_EN、ESP_BOOT_N、六根DSI、I2C1和所有电源。辅助分析不能替代编译网表。
4. FPC1/FPC2必须核对接触面、PIN1方向、上接/下接和屏软排线方向；FPC2.7/.8可能是机械固定脚，按实际连接器图纸处理，不当作第7/8根触摸信号。
5. PCB阶段保持DSI/RF/USB/MII/SDRAM信号下方连续参考地。不要为了所谓“天线效应”大面积挖掉数字地；RF天线净空按天线设计单独处理。CAN隔离区则必须真正分开两个电源/地系统。

## 6. 推荐修改顺序与上电验证

先修改：U7/BOOT0 -> USB电源与检测 -> LCD独立电压 -> VBAT方向/隔离 -> PDR_ON固定态 -> Flash片选、ESP电源/晶振 -> PHY参考电源/端接 -> 背光局部去耦 -> 位号、编译和封装。

首次验证建议分模块、限流上电：

1. 暂不接电脑、屏幕和外部CAN供电，先测12V/5V/3.3V、启动波形和LDO温升，确认BOOT0/PDR_ON。
2. SWD连通，检查MCU时钟；分别验证Flash JEDEC ID和测试区域读写、EEPROM、SDRAM全地址测试。
3. 验证ESP EN/BOOT启动和STM32/外部下载器互斥；WiFi发射时示波器观察芯片侧电源跌落。
4. USB只通信测试：12V关闭时插电脑，不应给主板反向供电；12V开启后能正确检测插拔并枚举。
5. 确认屏电压和连接器方向后接屏；先初始化/显图，后开背光并测20mA级电流。
6. PHY先检查25MHz、复位和管理寄存器，再测网络链路；CAN在总线侧供电正确、两端终端配置正确时通信测试。
7. 最后与功率板联调，测试MCU复位、升级中断、通信掉线等情况下输出是否保持安全状态。

本报告只给出当前保存版的检查和修改建议；以上实验尚未执行，不能视为测试通过记录。
