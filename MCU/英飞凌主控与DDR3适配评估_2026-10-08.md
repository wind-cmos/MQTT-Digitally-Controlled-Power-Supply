# 英飞凌主控与 DDR3 适配评估

日期：2026-10-08。

最新状态：用户已取消 DDR 要求，并改回单 MCU，ST/英飞凌均可。本文件保留为历史评估，不再作为当前选型约束；当前方案见《单MCU千兆方案_ST与英飞凌_2026-10-08.md》。

新增要求：英飞凌主控、较成熟且资料/案例充足、可参考开源项目，并增加 DDR3。继续保留此前“实际接近千兆吞吐”与现有功能的要求。

## 1. 结论与选型状态

本轮没有找到已经确认能同时满足上述全部条件、可直接定型的英飞凌单芯片方案，因此未修改 AD 原理图或 PCB，也未把任何候选型号标记为最终替代料。

“没有确认合格型号”不等于声称英飞凌所有产品绝无可能，而是现有公开资料不足以支持本项目直接定板。

不能把以下概念混为一谈：

- 千兆 MAC 不等于接近千兆的应用层吞吐。
- HyperRAM / HyperBus 不等于 DDR3；接口上使用双沿传输也不代表兼容 DDR3。
- LPDDR4 不等于 DDR3 / DDR3L，不能直接替换焊接。
- MIPI CSI 摄像头输入不等于 MIPI DSI 屏幕输出。
- 有示例源码不等于有“千兆吞吐 + DDR3 + DSI + 三路隔离采集”的完整开源整机。

上一版报告中的 RT1176 推荐以 SDRAM 为外部存储方案；新增 DDR3 硬要求后，该推荐不能直接沿用。RT1176 的 SEMC SDRAM 接口不是 DDR3 控制器。

## 4. 吞吐证据仍不足以直接定板

尚未确认上述候选在本项目工作负载下达到此前建议的单方向有效吞吐 ≥900 Mbit/s。

例如，2025 年英飞凌 XMC7200 官方社区讨论中，技术支持曾给出特定配置下约 41.5 Mbit/s 的 TCP 测试结果，同时继续排查配置和驱动。这个结果不是芯片上限，也不能代表当前软件最终性能；它说明“有千兆 MAC”和“示例已经跑满千兆”是两个不同结论。[原始讨论](https://community.infineon.com/t5/XMC/Ethernet-driver-XMC7200-edd-c-cy-ethif-c-current-state/td-p/944279)

定型前必须获取或建立可复现测试：具体芯片/步进、频率、PHY、SDK版本、TCP/UDP、包长、收发方向、缓存位置、显示/采集并发和接收端丢包统计。不能拿发送端发包速率代替实际接收吞吐。

## 5. DDR3 加入后，必须先确定什么

1. 主控是否具有明确支持该代际 DRAM 的控制器和 PHY；GPIO、普通 SPI、HyperBus 不能直接代替。
2. 是 DDR3、DDR3L 还是允许 LPDDR4；容量、位宽、速率和具体颗粒需要与控制器支持表匹配。
3. “模块”是板载 BGA 颗粒、带控制器的小板，还是 SO-DIMM 内存条。三者的引脚、电气和软件要求不同。
4. 上电初始化、时序训练、地址映射、DMA 可达性、仲裁和缓存一致性。
5. 电源/参考/端接、层叠、阻抗、DQS 字节组及厂商布局约束。

DDR3 只能增加缓存能力，不能提高现有 ADS1120 的采样率或 SD 卡持续写速，也不是断电保存数据的介质。

例如假设有效网络输入 112.5 MB/s、存储写入 20 MB/s、可用缓存 256 MiB：

$$
t_{\mathrm{fill}}=\frac{C}{B_{\mathrm{in}}-B_{\mathrm{out}}}
=\frac{256\times2^{20}}{(112.5-20)\times10^6}
\approx2.90\ \mathrm{s}
$$

这只是容量举例，并非建议已确认要配 256 MiB；它说明大 RAM 不能补偿长期输入速度大于输出速度。

## 6. 建议的下一步决策

- 如果英飞凌、DDR3、现有 DSI 屏幕、近千兆吞吐、成熟公开整机案例均不可妥协：目前不能给出已验证合格的单芯片料号，应先补齐厂商确认和性能证据，不应直接改板。
- 如果英飞凌优先且内存可变：工业控制方向可从 XMC7200 评估，但须接受内存/显示架构变化；重视图形与大内存则继续评估 CYT4EN + LPDDR4，同时验证显示和吞吐，不承诺其成熟度已达到要求。
- 如果英飞凌只需承担实时控制：可另设带 DDR3/DDR3L 的应用处理器承担网络、显示和存储。但这是双处理器新架构，必须先获用户确认；大流量应在应用处理器本地流转，不能经低速 SPI 来回搬运全部千兆数据。

待用户确认的首要问题：DDR3 是指定且不能更改的器件要求，还是“希望增加大容量外部内存”，允许改为 LPDDR4？其次需明确是否允许额外应用处理器或更换显示接口。
