# 整机高速性能评估与主控更换方案

评估日期：2026-10-08。对象：数控电源项目 MCU、BACK、MMT 原理图。

后续约束更新：用户最终取消 DDR 要求，改为单颗 ST/英飞凌 MCU，优先评估英飞凌。本文 RT1176 / MP255F 等建议保留为历史比较，不代表当前已定型号；最新方案见同目录《单MCU千兆方案_ST与英飞凌_2026-10-08.md》。下文原理图问题与性能预算仍可作为核查依据。

状态：完成原理图静态核查、带宽预算和主控选型建议；尚未完成新主控球位分配、原生 Altium ERC/ECO、PCB 改版及实机性能验证。本次没有修改 SchDoc、PcbDoc。

## 1. 先给结论

1. 现有 STM32F769IIT6 不满足“千兆链路且接近千兆实际吞吐”的要求，建议更换主控。问题不只是主频：它的原生以太网 MAC 只有 10/100 Mbit/s，且接口与当前 RTL8211FI 不兼容。
2. 保留 MCU / RTOS 开发方式的首选候选是 NXP MIMXRT1176CVM8B，工业级 Cortex-M7 800 MHz + Cortex-M4 400 MHz。它同时具备千兆 MAC 和 MIPI DSI，适合保留当前显示、隔离采集和电源控制的功能架构。
3. 如果要求“接近千兆 TCP + 约 100 MB/s 持续落盘 + 屏幕刷新”同时成立，建议优先采用 STM32MP255F + DDR + 高速存储的平台。它属于 MPU，不是 F769 的直接替换品，软件通常变为 Linux + 实时核。
4. 只换主控仍不能让整机都变快。当前 ADS1120 是低速精密 ADC；SD 卡接口、外部 SDRAM、DAC 后级滤波和电源闭环分别有自己的上限。
5. 现有原理图还有确定的网络接口、USB、BOOT0 等问题。必须修复，不能认为换一个更强的主控就自动解决。

F769 的 MAC、接口和核心规格依据：[ST STM32F769 数据手册](https://www.st.com/resource/en/datasheet/stm32f769ii.pdf)。新主控规格依据：[NXP RT1170B 工业级数据手册](https://www.nxp.com/docs/en/data-sheet/IMXRT1170BIEC.pdf)、[ST STM32MP255F 产品资料](https://www.st.com/en/microcontrollers-microprocessors/stm32mp255f.html)。

## 2. “千兆吞吐”应怎样定义

### 2.1 链路速率与应用数据不是一个数

网口显示 1000 Mbit/s，只证明协商到千兆，不能证明 CPU、TCP/IP、内存或存储达到千兆。

原始速率换算：

$$
B_{\mathrm{raw}}=\frac{R_{\mathrm{link}}}{8}
=\frac{1000\ \mathrm{Mbit/s}}{8}
=125\ \mathrm{MB/s}
$$

以 MTU 1500、IPv4、无 VLAN、无 TCP 选项为简化例子，一帧携带 TCP 数据 1460 字节，线上的帧、前导码和帧间隔合计 1538 字节：

$$
R_{\mathrm{TCP,ideal}}
=R_{\mathrm{link}}\frac{1460}{1538}
=1000\times\frac{1460}{1538}
\approx949.3\ \mathrm{Mbit/s}
$$

这只是单方向满尺寸报文的理想上限，不包含重传、软件处理不足等损失。不能把 125 MB/s 当成普通 TCP 文件传输的必达值，也不能把 RX 和 TX 相加达到 1 Gbit/s 说成单方向千兆。

### 2.2 本方案暂定的验收口径

用户已明确需要实际吞吐，但尚未明确协议、包长、双向并发和存储要求。因此先采用以下设计假设，不冒充已经确认的项目指标：

| 项目 | 暂定目标 / 必须说明的条件 |
|---|---|
| 链路 | 1000BASE-T、全双工 |
| 内存到网络 / 网络到内存 | 大包，单方向有效吞吐目标 ≥900 Mbit/s，分别测试 TX、RX |
| TCP 与 UDP | 分别测；UDP 以接收端有效数据及丢包率计，不能只看发送速率 |
| 同时收发 | 如需要，分别规定每个方向目标，不能用总和代替 |
| 网络到存储 | 若需要，单独验证约 100 MB/s 持续写入，而不是短时写入 RAM 缓存 |
| TLS、文件系统、业务解析 | 若产品实际启用，必须在开启状态复测 |
| ADC / 电源控制 | 另外规定采样率、更新周期和最坏延迟，不从网速推导 |

## 3. 现有硬件：主要瓶颈在哪里

| 模块 | 原理图中的器件 / 接法 | 本轮判断 |
|---|---|---|
| 主控 | U1：STM32F769IIT6，LQFP176 | 原生 MAC 百兆，不能达到目标 |
| 以太网 PHY | U21：RTL8211FI-CG，RGMII | PHY 支持千兆，但 F769 没有匹配的 RGMII 千兆 MAC，当前还存在错接 |
| 外部内存 | U9：IS42S16400J，16 bit、64 Mbit，即 8 MiB | 容量和共享带宽都应重新预算；不能当长期高速缓存 |
| 精密采样 | 每块 MMT 的 U14：ADS1120 | 单转换器最高 2 kSPS；不是四通道同时各 2 kSPS |
| 电压 / 电流设定 | MMT U13：DAC8552，后接 RC 和模拟 CC/CV 环路 | 寄存器写入速度不等于电源输出响应速度 |
| 模块通信 | SPI2、SPI4、SPI5 经背板和数字隔离器 | 可保留三条独立总线，但时钟受从设备、隔离传播和布线限制 |
| SD | 当前已接 D0～D3、CLK、CMD | 已是四位接线；当前常规 3.3 V 高速设计不能按 100 MB/s 持续存储使用 |
| SPI Flash | 主控侧两颗 W25Q32，普通 SPI 接法 | 适合参数 / 升级文件，不适合千兆连续记录 |
| 显示 | 双数据通道 MIPI DSI，触摸走 I2C | 新主控必须保留 DSI 或另外更换屏幕 / 加桥接 |
| USB | 当前 MCU 使用 USB FS D+/D− | 12 Mbit/s 链路，不是 USB HS，更不是千兆存储出口 |
| ESP32-C3 | UART 连接 | 适合无线配置 / 辅助通信，不能承担千兆主数据通道 |
| CAN / I2C | 控制与配置接口 | 不应拿来承担大批量高速数据 |

### 3.1 为什么保留 F769、只换 PHY 不行

F769 的 MII / RMII 是百兆 MAC 接口。RTL8211FI 使用 RGMII；其降低链路速率不等于把主机接口变成 MII。相同名字中的 TXD0、TXD1 不代表时序、时钟方向相容。

普通外挂网络芯片也不能消除主机侧瓶颈：

- F769 SPI 标称最高 54 Mbit/s，对应原始 6.75 MB/s，远低于千兆。
- 当前 USB FS 为 12 Mbit/s；即使另做外置 ULPI 的 USB HS，480 Mbit/s 原始链路仍低于 1 Gbit/s。
- 通过并行接口、FPGA 和外部 MAC 可以构造更复杂方案，但必须重新验证处理器、总线和协议栈。它不是简单换 PHY 的低风险修补。

因此本次不再把“F769 + 低速接口外挂千兆模块”作为满足用户吞吐目标的主方案。[F769 官方手册](https://www.st.com/resource/en/datasheet/stm32f769ii.pdf)

### 3.2 ADC：当前是精密监测，不是高速波形采集

MMT 的 ADS1120 四个输入分别接 U_MON、U_SET_OUT、I_MON、I_SET_OUT，共用内部转换器。其最高标称输出数据率为 2000 SPS；20 SPS 等较低速率的噪声 / 工频抑制优势不能直接套到最高速率。[TI ADS1120 数据手册](https://www.ti.com/lit/ds/symlink/ads1120.pdf)

按单颗 ADC 的最高原始数据量估算：

$$
B_{\mathrm{ADC}}=f_s\frac{N_{\mathrm{bit}}}{8}
=2000\times\frac{16}{8}
=4000\ \mathrm{B/s}
$$

若背板三个模块均采用相同 MMT，每块一颗 ADC：

$$
B_{\mathrm{3modules}}=3\times4000
=12000\ \mathrm{B/s}=12\ \mathrm{kB/s}
$$

这是裸采样数据，未加时间戳、状态和协议；不能再乘四个输入通道。四路等分扫描的理想预算至多约 500 SPS/路，实际还需扣除切换、启动和软件开销；四路也不是同时采样。

另外，ADC 的 DRDY 接到 MCP23S17 的 GPA1，再经扩展器 INTA / IRQ 回主控，不是直接到 MCU。现有低速监测可用，但固件要正确配置和清除中断；将来高速采样应增加直接 DRDY / CNV / 同步信号，经专用隔离通道到主控定时器 / DMA。

结论：

- 如果只需要数值显示、低速记录、远程电源设定，现有 ADC 路线有合理性。
- 如果要观察快速负载跳变、微秒级瞬态或高速 U/I 同步波形，需新增 / 更换 ADC、模拟前端和隔离链路。只换 MCU 无效。
- 比较稳妥的升级方向是保留 ADS1120 做精密低速监测，增加高速同步采样支路；型号要由采样率、同步通道数、噪声和输入范围决定。

### 3.3 DAC 与电源输出：不能用 SPI 时钟代表响应速度

当前 DAC8552 使用 3.3 V 供电。对应条件下串行接口最高 20 MHz，不能直接套用更高供电条件的 30 MHz 指标；一次写入包含 24 bit。[TI DAC8552 数据手册](https://www.ti.com/lit/ds/symlink/dac8552.pdf)

例如暂以 5 MHz SPI 计算一条命令的纯移位时间：

$$
t_{\mathrm{write}}=\frac{N_{\mathrm{bit}}}{f_{\mathrm{SPI}}}
=\frac{24}{5\times10^6}
=4.8\ \mu s
$$

这还不包括片选间隔、总线竞争和模拟建立时间。DAC 的大信号建立时间为微秒量级，不能将“能快速写寄存器”当成“输出端立即稳定”。

原理图还有显著的设定滤波：

- U_SET_OUT：R81 = 2.2 kΩ，C134 = 0.1 µF，随后还有 R65 和运放反馈网络。
- I_SET_OUT：R78 = 2.2 kΩ，C133 = 0.1 µF，随后还有 R36 和运放反馈网络。

先只取单个无负载 RC 作为数量级参考：

$$
\tau=RC=2.2\times10^3\times0.1\times10^{-6}
=220\ \mu s
$$

$$
f_{RC}=\frac{1}{2\pi RC}
=\frac{1}{2\pi\times220\times10^{-6}}
\approx723\ \mathrm{Hz}
$$

这不是整个闭环的精确截止频率：后级电阻和运放会改变等效阻抗，电源功率级、输出电容、负载及下拉放电电路又带来其他动态。准确响应要通过闭环模型、环路增益和负载 / 设定阶跃实测获得。

不要为追求“高速”直接删除 C133/C134；这可能引入噪声、过冲或失稳。千兆通信也不能替代硬件过流、过压、过温关断。

### 3.4 SPI 与隔离器：最高速率由整条链路决定

ADS1120 的 SCLK 最小周期 150 ns：

$$
f_{\mathrm{SCLK,max}}=\frac{1}{t_{\mathrm{SCLK,min}}}
=\frac{1}{150\times10^{-9}}
\approx6.67\ \mathrm{MHz}
$$

它已经远低于新 MCU 的最高 SPI 时钟。MCP23S17 在当前供电条件下的时序约束也必须单独遵守。[ADS1120 时序表](https://www.ti.com/lit/ds/symlink/ads1120.pdf)、[Microchip MCP23S17 数据手册](https://ww1.microchip.com/downloads/aemDocuments/documents/OTH/ProductDocuments/DataSheets/20001952C.pdf)

不能把数字隔离器的 150 Mbit/s 数据率直接当成 150 MHz SPI。尤其 MISO 有“时钟先穿过隔离器到从机、数据再穿过隔离器返回”的往返延迟。预算应包含：

$$
t_{\mathrm{available}}
>
t_{\mathrm{iso,SCK,max}}
+t_{\mathrm{slave,DO,max}}
+t_{\mathrm{iso,MISO,max}}
+t_{\mathrm{PCB}}
+t_{\mathrm{setup,MCU}}
+t_{\mathrm{margin}}
$$

按实际 SPI 模式确定可用采样窗口，使用最大传播延迟和最坏温压条件，不用典型值代替。各从设备分别设置合法时钟 / 模式，先低速验证再提高。[Skyworks Si864x 数据手册](https://www.skyworksinc.com/-/media/SkyWorks/SL/documents/public/data-sheets/si864x-datasheet.pdf)

### 3.5 SD 卡：当前已经四位，但不是千兆存储

当前主控接线是：

| 信号 | F769 引脚 |
|---|---|
| SDMMC1_D0 / D1 | PC8 / PC9 |
| SDMMC1_D2 / D3 | PC10 / PC11 |
| SDMMC1_CK | PC12 |
| SDMMC1_CMD | PD2 |
| SD_DETECT | PI8 |

以四位、50 MHz、单沿传输为带宽估算例子：

$$
B_{\mathrm{SD,raw}}=\frac{Wf}{8}
=\frac{4\times50\times10^6}{8}
=25\ \mathrm{MB/s}
$$

该例不是已经配置的固件时钟，也不表示有效写速能达到 25 MB/s。卡内部擦写、文件系统、协议开销和长尾停顿会进一步降低持续性能。当前图没有完整的 1.8 V UHS 电压切换设计，不能凭“卡支持 UHS”推断整机支持。

如果数据以 112.5 MB/s 进入、假设存储实际只能写 20 MB/s：

$$
\frac{dQ}{dt}=B_{\mathrm{in}}-B_{\mathrm{out}}
=112.5-20=92.5\ \mathrm{MB/s}
$$

缓存必然持续增长，任何有限 RAM 最终都会溢出。低速记录可保留 SD；持续接近千兆落盘必须同时改接口、存储器和软件。

### 3.6 内存与显示：大数据会多次经过同一内存

现有外部 SDRAM 容量为 8 MiB。即使全部用于缓存、没有任何数据排出：

$$
t_{\mathrm{buffer}}
=\frac{C_{\mathrm{buffer}}}{B_{\mathrm{in}}}
=\frac{8\times2^{20}}{125\times10^6}
\approx67.1\ \mathrm{ms}
$$

实际还要给帧缓冲、网络缓冲和程序数据留空间，可用缓存更少。

用历史屏幕方案中的 480×800、RGB565、假定 60 Hz 作预算例子；当前连接器没有锁定具体屏幕料号，因此该分辨率 / 刷新率不是本轮确认的硬件指标：

$$
C_{\mathrm{frame}}=W H b
=480\times800\times2
=768000\ \mathrm{B}
$$

$$
B_{\mathrm{scanout}}=W H b f
=480\times800\times2\times60
=46.08\ \mathrm{MB/s}
$$

双缓冲需要 1.536 MB；屏幕扫描只计算了读，还没有计算绘图写、混合和其他访问。

接收 900 Mbit/s 数据并在内存里额外复制一次，粗略总流量是：

$$
B_{\mathrm{memory}}
=B_{\mathrm{DMA,write}}+B_{\mathrm{copy,read}}+B_{\mathrm{copy,write}}
=3\times\frac{900}{8}
=337.5\ \mathrm{MB/s}
$$

例如 16 bit SDRAM 若以 100 MHz 工作，理论总线峰值只有：

$$
B_{\mathrm{SDRAM,peak}}=\frac{16}{8}\times100\times10^6
=200\ \mathrm{MB/s}
$$

100 MHz 是举例，不是对当前固件频率的确认；刷新、行切换和仲裁还会降低可用带宽。新方案必须避免盲目多次复制，并核查 DMA 可访问的 SRAM 区域、缓存一致性和描述符对齐。

## 4. 主控更换：建议的两条路线

### 4.1 默认 MCU 路线：MIMXRT1176CVM8B

这是保留 MCU / RTOS 模式的推荐候选，不是已通过整机验证的最终 BOM。

| 选型项目 | 对本项目的意义 |
|---|---|
| 工业级 M7 800 MHz + M4 400 MHz | 将网络 / 图形与实时控制分工；不把消费级 1 GHz 指标套到该料号 |
| 原生千兆以太网 MAC | 可连接 RGMII 千兆 PHY |
| 原生两数据通道 MIPI DSI | 与当前屏幕接口方向一致，仍需核对屏幕初始化和电气要求 |
| 片内 RAM 2 MB，启用 ECC 后容量有变化 | 比当前片内资源充裕，但仍需外部内存预算 |
| 6 SPI、6 I2C、多 UART、3 CAN FD、2 uSDHC | 外设数量适合当前三组隔离 SPI、双 I2C、CAN、SD 和无线协处理器 |
| SEMC / FlexSPI | 外部 SDRAM 和启动 Flash 需要重新设计 |
| 289 球 MAPBGA，14×14 mm、0.8 mm 间距 | 无法与现有 LQFP176 原位替换 |

具体派生型号的资源和复用约束以[工业级 RT1170B 数据手册](https://www.nxp.com/docs/en/data-sheet/IMXRT1170BIEC.pdf)为准。“数量够”还不等于所有接口在该封装上可以同时无冲突引出。

性能证据的边界：NXP 技术支持曾公布 RT117x CM7 的 iperf UDP TX 954 Mbit/s、RX 905 Mbit/s。但帖子未完整锁定本项目的工业级料号、800 MHz、内存布局、SDK、TCP 和全部并发负载，讨论中也存在 SDK / 驱动版本差异。因此它证明存在接近千兆的实现经验，不能当成本板保证值，也不应照抄旧 SDK 作为新项目版本选择。[NXP 官方支持讨论](https://community.nxp.com/t5/i-MX-RT-Crossover-MCUs/RT117x-ENET-1G-performaces/m-p/1995745)

建议职责划分：

- M7：以太网协议栈、显示、文件系统、升级包验证和非实时业务。
- M4：MMT 通信、设定更新、实时状态监控和超时处理。
- 两核通过明确的共享缓冲和消息机制交换数据，不同时随意访问同一外设。
- 硬件保护独立于两核运行状态；网络拥塞和 GUI 卡顿不能阻止关断。

外部 RAM 建议从 32～64 MiB 容量级做资源预算，并优先核算 32 bit SDRAM 的球位和实际可用带宽。这个范围是设计建议，不是需求测算后的定型值。不能简单复制现有 8 MiB / 16 bit 电路后宣称足够。

### 4.2 高速并发 / 持续存储路线：STM32MP255F

如果“高速”明确包括大流量 TCP、持续记录、大缓存和图形并发，优先考虑这条路线。

- 双 Cortex-A35 最高 1.5 GHz，Cortex-M33 最高 400 MHz。
- 具备千兆以太网、DSI、DDR、PCIe / USB 3.0 等接口。
- 可选择 STM32MP255FAI3 的工业级 436 球、0.8 mm 封装作为球位评估起点；仍须在工具中完成并行外设分配。
- A35 / Linux 负责网络、存储和界面；M33 / 实时固件负责电源控制接口。

上述是产品能力，不是本板吞吐量实测。[ST STM32MP255F 官方资料](https://www.st.com/en/microcontrollers-microprocessors/stm32mp255f.html)

建议从 DDR + eMMC 启动 + PCIe NVMe 数据盘的系统结构评估；例如 512 MiB DDR 是初始容量预算，不是强制最小值。也可评估 USB 3.0 SSD，但 MP25 的 PCIe 与 USB 3.0 SuperSpeed 涉及共享 PHY，不能同时无条件占用；USB 2.0 的情况另行区分。[ST PCIe 外设说明](https://wiki.st.com/stm32mpu/wiki/PCIe_internal_peripheral)

eMMC 接口标称速率不等于具体 eMMC 芯片在最坏温度、剩余容量和寿命状态下的持续写速。若选 eMMC 记录，必须验证其最坏持续写入和停顿；NVMe 也不能省略实测。

这条路线改动较大：多路电源、上电时序、DDR、BGA、引导软件和 Linux 都要重新设计。可以先用开发板或适当核心板做性能原型；核心板必须实际引出本项目需要的 DSI、三组 SPI、I2C 等接口，不能只看处理器型号。

### 4.3 本轮选择规则

| 明确需求 | 推荐方向 |
|---|---|
| 保持 MCU / RTOS；千兆网络为主要新增目标；存储和采样仍保持现有低速用途 | RT1176 优先，原型达到吞吐门槛后再冻结新板 |
| 接近千兆 TCP，同时图形和约 100 MB/s 持续存储 | MP255F 优先，仍需端到端压测 |
| 不增加高速 ADC，只传现有三个模块的监测数据 | 数据量本身很小；千兆只是新增通信能力，不代表当前测量变快 |
| 微秒级 U/I 瞬态采集 | 除主控外，还必须改 ADC、同步、隔离及模拟前端 |

不推荐仅凭主频改为 H743 来解决千兆问题；其原生以太网仍是百兆。[ST STM32H743 数据手册](https://www.st.com/resource/en/datasheet/stm32h743vi.pdf) STM32N6 虽是另一类千兆 MCU 候选，但不能把其 MIPI CSI 摄像头输入当成 DSI 显示输出；当前 DSI 屏幕需求使它不是本次低改动首选。[ST STM32N6 数据手册](https://www.st.com/resource/en/datasheet/dm01125716.pdf)

## 5. RT1176 的功能迁移表：先锁资源，再锁球位

以下是资源分组，不是可直接接线的最终引脚表。禁止把旧 F769 的 PA / PB 名称硬套成新器件球位。

| 现有功能 | 当前接口 / 信号 | 新主控必须预留 | 迁移注意点 |
|---|---|---|---|
| 千兆网络 | 当前错误的 ETH 连接 | 一套千兆 RGMII、MDC、MDIO、PHY_RESET，可选 PHY_IRQ | TX/RX 两组各 4 数据 + 控制 + 时钟；核对 I/O 电压和时延 |
| 显示 | DSI 时钟 + 两对数据 | 原生 DSI、屏复位 | 核对屏幕料号、初始化表、帧率 |
| 触摸 / EEPROM | I2C1，触摸中断 / 复位 | 一套 I2C、独立 IRQ / RESET | 与背板 I2C 分开 |
| 背板配置 | I2C2 | 第二套 I2C | 上拉、电容、隔离器速率按整条总线设计 |
| 模块 1 | SPI2，CSA、CSB、IRQ | 一套独立 SPI + 片选 / 地址选择 + IRQ | 保持现有背板协议和片选译码含义 |
| 模块 2 | SPI4，CSA、CSB、IRQ | 第二套独立 SPI + 片选 / 地址选择 + IRQ | 由实时核管理为宜 |
| 模块 3 | SPI5，CSA、CSB、IRQ | 第三套独立 SPI + 片选 / 地址选择 + IRQ | 高速新增 ADC 时重新预算，不能无限扩展现有协议 |
| 升级 / 参数 Flash | SPI1，两颗 W25Q32 | 启动 FlexSPI + 独立分区或额外存储总线 | RT1176 外部启动，不能沿用 F769 内部 Flash 假设 |
| SDRAM | FMC 16 bit | SEMC，优先评估 32 bit | 容量、时钟、走线及引脚复用全部重新核算 |
| SD | SDMMC1 四位 + CD | uSDHC + CD | 可继续低速日志；不要默认千兆落盘 |
| ESP32-C3 | USART6 + EN / BOOT | UART + 两个 GPIO | ESP 自身 Flash 与主控启动 Flash 分开管理 |
| 外部串口 / 数字 IO | USART2 / DIN1 / OUT1 | UART 与数字 IO 的模式化分配 | 修正 74HC125 多源共网问题 |
| CAN | CAN1 + 隔离收发器 | FlexCAN | 使用 CAN FD 还需收发器、线缆及对端均支持 |
| USB | FS D+/D−、VBUS、EN、OC | USB 控制器及正确的 Type-C 角色电路 | 是否升级 HS 与是否 Host 要分开决定 |
| 编码器 | ENC_A、ENC_B、ENC_SW | 硬件正交解码 / 定时器 + 按键 IRQ | 不用高频软件轮询代替 |
| 背光 / 蜂鸣器 | TFT_BRIGHTNESS、DAC_OUT1 | PWM、GPIO | 有源蜂鸣器通常不需要占 DAC |
| 电源管理 | FAULT、PWR_DIRECT、PWR_SSTART、OE_SYNC、DIN2、OUT2 | 对应 GPIO / 同步定时资源 | 逐个定义上电默认状态和失联安全状态 |
| 时间基准 | RTC、32.768 kHz、RTC_REF | RTC / SNVS 与外部参考功能资源 | 根据真正的外部参考用途重新选路由 |
| 调试 / 救援 | SWD、NRST、BOOT0 | 新芯片规定的 SWD/JTAG、复位、Boot/恢复接口 | 不复用旧 BOOT0 触发器设计 |

球位分配的顺序建议：电源 / 启动 / 调试 → 内存 → RGMII → DSI → SD → 三组 SPI → USB / CAN / UART / I2C → PWM / 编码器 / 普通 GPIO。先用 NXP 配置工具同时启用这些资源，再生成完整球位表和原理图。

如果选择 MP255F，则按同一功能清单用对应 ST 工具重新分配，并确认实时核可访问的外设、隔离防火墙及核间资源归属。

### 6.1 优先修复：影响功能或存在电气风险

| USB 页，C54 / C55 | 两颗电容的低端互接，但未接 GND | 修复接地；当前不能发挥预期 VBUS 去耦作用 |
| USB 页，R21 / R22、U14 | CC1 / CC2 各 5.1 kΩ 下拉宣告 Sink；TPS2051B 又可以向 VBUS 供电 | 先确定 Device/Sink、Host/Source 或 DRP；不能宣告 Sink 后直接向外供电。连接电脑时禁止电源对顶 |

### 6.2 次优先：可靠性、时序和具体负载匹配

| 页面 / 位号 | 问题或待确认点 | 修改 / 验证要求 |
|---|---|---|
| Ethernet PHY，C70 / L7 | C70 = 0.1 µF 直接接 REG_OUT 与 GND，位于 L7 前 | REG_OUT 是内部开关电源相关节点，不能当普通直流电源脚随意去耦；必须对照厂商参考电路确认，属于高优先级待核实项 |
| Ethernet PHY，MDI 四对线 | PHY MDIP 接到当前标注 N、MDIN 接 P | 建议按物理磁性器件引脚规范纠正。自动极性纠正可能使链路仍工作，不能据此认定四对必然失效或认定接法合格 |
| Ethernet PHY，电压 / strap | DVDD_RG、CFG、PHY 地址及 TXDLY/RXDLY 影响运行 | 与新 MAC 的 I/O 电压、地址和内部时延配置统一；避免 MAC、PHY、PCB 同时重复加时延 |
| SD 页，CMD | TF1 CMD 经 R85 接 PD2，但没有外部上拉 | 按 SD 规范和卡座设计补适当上拉，例如 10 kΩ；已有 DAT0～3 上拉不能替代 CMD 上拉 |
| SD 页，CD / 卡座外壳 | SD_DETECT 无外部上拉；卡座壳脚接 PE，VSS 接 GND | 增加明确检测电平；核对 CD 触点实际连接的是壳还是独立触点，不能假设 PE 等于逻辑 GND |
| USB 页，PA9 分压 | 5.1 kΩ / 5.1 kΩ 将 5 V 分到约 2.5 V | 核对究竟用 GPIO 检测还是 USB 专用 VBUS 检测；换型后按新芯片阈值 / 掉电容限重算 |
| USB 页，背光 L1 / U12 | TPS61169 的 L1 = 3.3 µH；VIN 经 R19 后缺少就近对地电容 | 依据数据手册推荐范围和屏幕电流选电感，并在实际 VIN 节点就近去耦；不要把上游电容当作已跨过串联电阻的本地去耦 |
| USB 页，R20 / D3 | 电流设定 10 Ω，二极管 SS24 | 核对约 20.4 mA 是否适合实际 LED 串；检查二极管相对升压 / OVP 的电压裕量 |

| MCU_F7，VREF+ | R8 后没有看到对应 VREF+ 到 VSSA 的直接去耦 | 若保留此模拟参考用途，按芯片要求补；换型时全部按新器件电源域重新检查 |

本次也确认了部分已有改进：SD 四位线已接齐；两组 I2C 有各自上拉；当前 CAN 隔离电源的输出极性不能继续按旧版本问题重复判错。这些局部正确不代表整板已通过 ERC 或实测。

## 7. 新板设计的必要改动

### 7.1 不是只替换一个符号

1. 新主控封装、电源轨、上电时序、复位、启动脚、参考时钟和下载救援接口全部按新手册重做。
2. RT1176 的外部启动 Flash、MP255F 的启动介质和 DDR 均与 F769 内部 Flash 模式不同；旧 VCAP、BOOT0 电路不能复制。
3. RTL8211FI 可作为保留候选，但须核对当前版本参考电路、驱动、供电和 RGMII 电压；不能原封不动保留当前错误接线。
4. RGMII 是源同步并行数字接口，不是差分对。分别约束 TX 组、RX 组的时钟与数据关系；千兆模式为 125 MHz DDR。以厂商时序预算决定长度和时延，不给任意“全部等长到某毫米”的通用规则。
5. PHY 到变压器的四对 MDI、DSI 才按各自差分规范布线。确保参考平面连续、回流路径明确、远离功率开关节点。
6. 更新叠层、阻抗和 BGA 扇出后再评估层数与成本；未完成布局不能保证原板尺寸和原层数可直接保留。

### 7.2 软件是吞吐能否实现的一部分

- 使用 DMA 描述符环、批量收发和尽量少复制的数据路径。
- 描述符、缓存行和实际 DMA 可访问内存区域必须匹配。不要把 TCM / Cache 当成所有 DMA 都可透明访问。
- 采用硬件校验和等可用卸载功能时，驱动和协议栈配置必须一致，并验证报文正确性。
- 网络、GUI 和存储不能用长时间关中断保护大块操作。
- 为实时任务建立最坏执行时间、超时和看门狗，不只测平均 CPU 利用率。
- 升级采用带完整性 / 身份验证、断电恢复及回退机制的分区设计。正常在线升级不靠频繁切 Boot 引脚实现，ROM 恢复接口独立保留。

### 7.3 220 V AC 整机边界

本报告评估的是数字主控与已提供板卡的功能和性能，不构成 220 V AC 输入的安全或 EMC 合格结论。隔离模块额定耐压不能单独证明整机满足加强绝缘；PE / GND 策略、爬电距离、电气间隙、漏电流、接触安全、保险及保护元件要按最终产品类别另做审核。

## 8. 推荐执行顺序与验收

### 阶段 A：在改板前证明架构

1. 明确实际负载：通道数 × 采样率 × 位数；屏幕分辨率 / 帧率；TCP/UDP；是否加密；是否连续落盘。
2. 若选 RT1176，在原型上按所选工业级工作频率验证千兆，不用较高频率样机结果替代。
3. 分别测试 TCP、UDP 的 TX、RX，记录接收端数据率、CRC 错误、丢包 / 重传、CPU、内存占用和温度。
4. 再同时打开显示刷新、三组 SPI、CAN、触摸和存储，测试实际业务数据通路。
5. 达不到门槛则定位 CPU、内存、驱动或存储瓶颈；不要已经定板后才发现“千兆 MAC ≠ 千兆应用”。

### 阶段 B：冻结硬件

完成新主控全球位表、外设复用、I/O 电压、电源时序、实际屏幕及存储器选型。修复第 6 节问题后，在 Altium 原生编译 ERC、审阅 ECO，再更新 PCB；旧 PCB 文件不能当作已经与本次原理图同步。

### 阶段 C：整机验证

| 测试 | 建议验收方式 |
|---|---|
| 网络基础 | 1000BASE-T 全双工稳定协商，链路错误统计正常 |
| 有效吞吐 | 暂定大包单向 ≥900 Mbit/s；收、发分别达标，TCP / UDP 不混为同一个结果 |
| 并发吞吐 | 显示、采集和业务启用后仍满足已约定的吞吐目标 |
| 持续存储 | 若要求约 100 MB/s，使用超过缓存容量的数据量，包含实际持久化、卡 / 盘停顿和剩余容量条件 |
| 实时性 | 示波器 / 逻辑分析仪测 SPI 调度与设定更新最坏延迟，压测下不得越过控制要求 |
| 保护 | 网络阻塞、主核异常、通信中断等故障注入时，输出进入定义的安全状态 |
| 模拟性能 | 精度 / 噪声、负载阶跃、设定阶跃、过冲、恢复时间；不能仅凭数字接口速率判定 |
| 稳定性 | 建议先做至少 30 分钟持续并发压测，再做产品要求的长时间和温度边界测试 |
| 升级恢复 | 更新中断电、文件错误、启动失败等情形可恢复；救援接口实际可用 |

这里的时间和吞吐门槛是建议验收草案，不是已完成的实测结果。尚无当前固件或样机测试数据，不能对最终吞吐量、闭环带宽或 EMC 作保证。
